# 수학 던전 런 (가칭) — v0 구현 명세서 (Claude Code용)

> 이 문서를 프로젝트 루트에 `SPEC.md`로 두고, Claude Code에 아래 "시작 프롬프트"를 입력하세요.

## 0. 시작 프롬프트 (그대로 붙여넣기)

```
SPEC.md를 끝까지 읽고 v0를 구현해 줘.
순서: (1) 구현 계획과 파일 구조를 먼저 요약해서 보여주고 (2) 수학 엔진 + 단위 테스트부터 만들고
(3) 테스트가 통과하면 화면(UI)을 만들고 (4) 마지막에 SPEC.md의 "완료 기준"을 하나씩 직접 확인해 줘.
수학 계산은 반드시 정수 분수 연산으로 하고(부동소수점 금지), 정답은 코드가 검증해야 해.
SPEC에 없는 기능은 만들지 말고, 애매한 점은 추측하지 말고 나에게 질문해 줘.
```

## 1. 목표와 배경

- 대상: 초등학교 6학년. 교사가 수업 중 "오늘 배운 차시"에 맞춰 15분 안팎으로 쓰는 수학 게임.
- 핵심 컨셉: 오늘 배운 차시를 **차시 모듈(JSON)** 로 꽂으면 그날의 던전이 열리는 로그라이크 카드 게임.
- 핵심 원칙
  1. 수학이 곧 게임의 결정이다. 문제를 풀어 몬스터를 때리는 구조가 아니라, 수 카드를 골라 식을 만드는 선택 자체가 게임이다.
  2. 개념이 곧 능력이다. 개념을 정확히 쓰면 '개념 조커'를 얻고, 조커가 이후 점수를 키운다.
  3. 오답은 감점이 아니라 정보다. 틀린 이유를 보여주는 단서를 주고 재도전하게 한다.
  4. 엔진 1개 + 차시 모듈 + 게임 모드. 차시가 늘어도 엔진 코드는 바뀌지 않아야 한다.
- 이번 v0 범위: **카드 조립 모드 1종 + 6학년 1학기 "분수의 나눗셈" 5차시.**
  (다른 모드와 단원은 v1 이후이며 이번에 만들지 않는다. 확장 가능한 구조만 잡아 둔다.)

## 2. 기술 제약

- 순수 HTML + CSS + JavaScript(ES 모듈). 빌드 도구, 프레임워크, 외부 CDN 의존 없음.
- 로컬 실행: `npx serve .` 또는 `python3 -m http.server`. GitHub Pages에 그대로 올릴 수 있어야 한다.
- 서버/DB 없음. 기록은 `localStorage`에 저장한다.
- 태블릿·크롬북 터치 사용을 기본으로 한다. 터치 영역 최소 44px, 가로 1024px 이상과 세로 768px 모두 깨지지 않게.
- UI 언어는 한국어. 코드 식별자와 주석은 영어, 사용자에게 보이는 문구는 한국어.
- 개인정보 수집 없음. 학생은 닉네임(자유 입력, 최대 8자)만 사용한다.

## 4. 수학 엔진 규격

### 4.1 분수 (`fraction.js`)
- 표현: `{ n, d }` (정수, d > 0). 부동소수점 사용 금지.
- 필수 함수: `gcd`, `reduce`, `divide(a, b)`, `multiply`, `compare`, `equals`, `isProper`, `toMixed(f)` → `{whole, n, d}`, `fromMixed`, `toDisplay(f)`.
- `toDisplay`는 기약분수 기준으로 문자열/구조를 돌려준다(화면에서 분수는 위·아래로 그린다).

### 4.2 의뢰(Quest) 생성 (`quests.js`)
한 의뢰 = 카드 손패 + 목표 유형 + 정답 판정 규칙.

- 손패: 1~9 수 카드 6장(중복 허용). 한 의뢰에서 쓰는 카드는 차시 모듈이 정한 개수(`pick`).
- 목표 유형 3가지
  - `max`: 만들 수 있는 몫 중 **가장 큰** 식을 만든다.
  - `min`: **가장 작은** 식을 만든다.
  - `target`: 몫이 지정된 값(예: 3/8)이 되게 만든다.
- 최적해는 가능한 모든 카드 선택·배치를 **브루트포스로 전부 계산**해 정확한 분수로 비교한다(6장 중 최대 4장 선택이므로 충분히 빠름).
- `target` 의뢰는 해가 반드시 존재하도록 생성한다. (먼저 임의의 해를 만들고, 그 해를 손패에 포함시키는 방식.)
- 같은 몫이 되는 서로 다른 식은 모두 정답으로 인정한다(`max`에서는 최적값과 같은 몫이면 정답).
- 재현 가능한 테스트를 위해 난수는 시드를 받는 함수(`mulberry32` 등)로 만든다.

### 4.3 판정
학생 행동은 두 단계다.
1. **식 만들기:** 카드를 골라 식을 구성한다. (이 선택의 질이 `선택 점수`)
2. **답 입력:** 그 식의 몫을 분수로 입력한다. (`계산 점수`)

판정 결과는 다음 값을 가진다: `expressionOptimal`(목표 충족/최적 여부), `answerCorrect`, `answerReduced`(기약분수 여부), `errorTag`(아래 오개념 태그와 매칭).

## 5. 차시 모듈 스키마 (`data/lessons/*.json`)

```json
{
  "id": "6-1-u1-l3",
  "unit": "6-1 1단원 분수의 나눗셈",
  "title": "(분수)÷(자연수)를 알아볼까요",
  "standardNote": "교과서 지도서의 차시별 성취기준을 여기에 그대로 옮겨 적는다 (코드: TODO 교사 확인)",
  "mode": "cardAssembly",
  "expression": "frac_div_nat",
  "pick": 3,
  "questTypes": ["max", "min", "target"],
  "constraints": { "properFractionOnly": true, "numeratorMultipleOfDivisorBias": true },
  "concepts": [
    { "id": "reduce", "name": "약분 조커", "effect": "answerReduced ? x2 : x1",
      "unlockCondition": "answerReduced && requiredReduction", "description": "약분해서 기약분수로 답했을 때 점수 2배" }
  ],
  "misconceptions": [
    { "tag": "divide_denominator", "pattern": "분모를 나눈 답", "hint": "분수를 똑같이 나누면 분모가 아니라 어떤 부분이 나뉘는지 그림으로 생각해 봐!" },
    { "tag": "multiply_to_numerator", "pattern": "나누는 수를 분자에 곱한 답", "hint": "나누면 양이 줄어야 해. 답이 처음보다 커졌어?" }
  ],
  "bossQuiz": { "type": "findWrongLine", "count": 1 }
}
```

- `expression` 값(엔진이 지원해야 하는 식 유형)
  - `nat_div_nat` : a ÷ b (몫을 분수로) — 1차시(a<b), 2차시(a>b, 대분수 표기 요구)
  - `frac_div_nat` : (a/b) ÷ c — 3차시(분자가 c의 배수 위주), 4차시(곱셈식으로 변환하여 답)
  - `mixed_div_nat` : (w a/b) ÷ c — 5차시
- 새 차시를 추가할 때 **엔진 코드를 고치지 않고 JSON만 추가**해도 동작해야 한다(`expression`이 기존 유형일 때).
- 학생이 "오늘의 차시"를 고르는 화면은 `data/lessons/` 목록(인덱스 JSON `data/lessons/index.json`)에서 읽는다.

### 5차시 구성 (6-1 1단원, 교과서 출판사별로 순서가 다를 수 있음)

| 차시 | 제목 | expression | 핵심 오개념 태그 |
| --- | --- | --- | --- |
| 1 | (자연수)÷(자연수)의 몫을 분수로 (1) | nat_div_nat (a<b) | `reverse_fraction` (3÷4를 4/3으로) |
| 2 | (자연수)÷(자연수)의 몫을 분수로 (2) | nat_div_nat (a>b) | `mixed_whole_only` (대분수 정수부분만 계산) |
| 3 | (분수)÷(자연수) | frac_div_nat | `divide_denominator`, `multiply_to_numerator` |
| 4 | (분수)÷(자연수)를 분수의 곱셈으로 | frac_div_nat (곱셈 변환 입력) | `forgot_reciprocal` (÷c를 ×c로) |
| 5 | (대분수)÷(자연수) | mixed_div_nat | `mixed_whole_only` |

오개념 태그는 **학생 오답을 코드로 계산해 역으로 매칭**한다(예: 학생 답이 `a/(b÷c)`꼴이면 `divide_denominator`). 매칭되지 않으면 일반 힌트를 보여준다.

## 6. 게임 규칙 (한 판 = 의뢰 3개 + 보스 1개, 약 15분)

1. **차시 선택** → 닉네임 입력(저장된 닉네임 있으면 자동) → "던전 입장".
2. **의뢰 고르기:** 의뢰 3개(쉬움/보통/도전) 중 하나를 고른다. 난이도는 카드 수와 목표 유형으로 조절한다(쉬움=`target`, 보통=`max`/`min`, 도전=카드 4장+`max`).
3. **의뢰 플레이:** 손패 6장 → 식 만들기 → 답 입력. 제출 전에는 몇 번이든 카드를 바꿀 수 있다. **제출 후 틀리면** 오개념 힌트를 보여주고 재도전 1회(두 번째 제출부터 기본 점수 50%).
4. **점수:** 기본 점수 100. 선택 점수(식이 목표/최적) 50 + 계산 점수(정답) 50. 힌트를 본 뒤 정답이면 계산 점수 절반.
5. **개념 조커:** 의뢰를 마치면 조건을 충족한 개념 조커가 열리고, 조커 3개 중 1개를 골라 이후 점수에 적용한다(최대 3장 보유). 조커 효과는 `scoring.js`에서 **데이터(차시 모듈의 `effect`)를 해석**해 적용한다. 임의의 수식 문자열을 `eval`하지 말고, 허용된 효과 종류(`multiplier`, `bonusFlat`) 객체로 정의한다.
5-1. 예시 조커: 약분 조커(기약분수로 답하면 점수 ×2), 곱셈 변환 조커(4차시: 곱셈식 변환 단계를 올바르게 입력하면 +30), 몫 어림 조커(답 입력 전에 "몫이 처음 분수보다 커질까/작아질까"를 맞히면 +20).
6. **보스(수사):** 풀이 4줄 중 **틀린 줄 1개**를 찾고, 이유를 보기 3개 중에서 고른다(`bossQuiz`). 오개념 목록의 `pattern`으로 틀린 풀이를 자동 생성한다. 정답이면 보스 격파.
7. **정리 화면:** 점수, 가장 쓸모 있었던 개념 조커, 자주 틀린 유형(오개념 태그)을 보여주고, 성찰 질문 1개("오늘 가장 도움이 된 개념 카드는?")에 보기를 골라 답하게 한다. 이 답도 기록한다.
8. **개인 기록:** 닉네임별 최고 점수와 최근 5판을 `localStorage`에 저장한다. (실시간 순위/경쟁 표시는 만들지 않는다. 소규모 학급을 고려해 "내 기록 갱신"을 중심으로 한다.)
9. **시간 제한은 기본 꺼짐.** 설정에서 켤 수 있는 옵션으로만 제공한다(수학 불안을 고려).

## 7. 화면 목록

1. 시작 화면: 차시 선택 카드 목록 + 닉네임 입력
2. 의뢰 선택 화면 (3개 카드)
3. 의뢰 플레이 화면: 손패(위), 식 조립 영역(가운데, 분수를 위·아래로 표시), 답 입력(분수 입력 위젯: 자연수/분자/분모), 제출 버튼, 힌트 영역
4. 조커 선택 화면
5. 보스 화면
6. 정리 화면
7. 교사 화면 (`?teacher=1`): 차시별·오개념 태그별 정답률, 최근 기록 목록, **CSV 내보내기**, 기록 초기화(확인창 포함)
8. 설정: 시간 제한 켜기/끄기, 효과음 켜기/끄기(효과음은 v0에서 생략 가능)

UI 가이드: 카드는 크게, 한 화면에 하나의 결정만 보여 준다. 정답/오답 색에만 의존하지 말고 아이콘·문구도 함께 쓴다(색각 대응). 분수는 `font-size`를 크게, 글꼴은 시스템 한글 글꼴.

## 8. 스킨(theme) 구조

게임의 이름, 마스코트, 배경색, 의뢰/조커 아이콘(이모지)은 `data/theme.json` 한 파일로 바꿀 수 있게 한다. 코드에 한국어 게임 이름·캐릭터 이름을 하드코딩하지 않는다. (학생 투표로 스킨을 정할 예정이므로 파일만 교체하면 되어야 한다.)

## 9. 기록과 집계 (`log.js`)

한 의뢰 제출마다 한 줄을 저장한다.

```
{ t: ISO시각, nick, lessonId, questType, expression, hand, expr, answer,
  expressionOptimal, answerCorrect, answerReduced, errorTag, hintUsed, retry }
```

- 집계: 차시별 정답률, 오개념 태그별 빈도, 평균 소요 시간.
- 교사 화면은 `?teacher=1`로만 열린다(비밀번호는 v0에서 두지 않지만, 교사 화면에서 학생 닉네임 외 정보는 보이지 않는다).

## 10. 테스트 (먼저 작성, 통과해야 UI로 넘어감)

필수 단위 테스트
- `fraction`: `gcd`, `reduce`, `divide`, `toMixed` (예: 3÷4=3/4, 7÷3=2 1/3, (3/4)÷2=3/8, (2 1/3)÷2=7/6=1 1/6).
- `quests`: 같은 시드 → 같은 의뢰. 모든 `target` 의뢰는 해가 존재. `max`/`min` 최적값이 브루트포스 결과와 일치. 1~9 카드 6장, 모든 `pick` 조합에서 0으로 나누지 않음.
- `scoring`: 재도전 감점, 조커 중첩, 힌트 사용 시 계산 점수 절반.
- 오개념 매칭: 3/4÷2에 대해 답 3/2 → `divide_denominator`, 6/4 → `multiply_to_numerator`, 3÷4에 대해 4/3 → `reverse_fraction`, (2 1/3)÷2에 대해 1 1/3 → `mixed_whole_only`.
